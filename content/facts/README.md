# 真实素材录入说明

合规闸门要求：笔记里的每一个具体数字都必须来自你的系统真实输出，
AI 不得编造。这个目录存放每天的素材。

## 用法

每条选题对应一个 JSON 文件，文件名 = 选题 id，例如 `A01.json`：

```json
{
  "slots": {
    "hook_ai": "想让 AI 直接把复盘报告写出来，省掉每天半小时整理",
    "failure": "它把我的记录写得特别顺，顺到有点不对——全是正确的废话",
    "lesson": "AI 最擅长的不是分析，是把「没有结论」写得像「有结论」",
    "fix1": "把输出格式改成固定字段，让它没有自由发挥的空间",
    "fix2": "所有它给出的判断，都必须能回指到我的原始记录里",
    "fix3": "加了一个「事实 / 推断」的分栏，把两者物理隔开",
    "result": "同样的数据，现在能看出到底哪一步走偏了",
    "method": "它说的每句话，我能不能在原始记录里找到出处"
  }
}
```

## 必填槽位

### 主线 A（搭系统日志）—— 8 个
| 槽位 | 含义 |
|---|---|
| `hook_ai` | 我一开始想让 AI 做什么 |
| `failure` | 它怎么翻车的（真实事件） |
| `lesson` | 从翻车里得出的道理 |
| `fix1` `fix2` `fix3` | 我改了三件事 |
| `result` | 改完之后的变化 |
| `method` | 沉淀下来的方法论 |

### 支线 B（回测科普）—— 8 个
| 槽位 | 含义 |
|---|---|
| `expectation` | 我原本的预期 |
| `result` | 实测结果暴露的落差 |
| `diagnosis` | 问题出在哪 |
| `key_factor` | 最要命的那一个因素 |
| `pitfall1` `pitfall2` `pitfall3` | 三个我踩过的坑 |
| `method` | 方法论总结 |

### 支线 B 额外：4 个口径槽位
正文开头的 `📌 数据区间` `📌 样本数量` `📌 成本假设` `📌 报告字段`，
在 JSON 里分别写作 `区间` `笔数` `成本假设` `报告字段`。

这 4 个**必须填**，否则正文会残留占位符，被合规闸门按
「真实素材槽位未填写」拦截，无法发布。

## 快速开始

最省事的做法：先不管 slots，用默认骨架跑通流程（默认文案已经合规），
等你有真实素材时再逐条覆盖。默认骨架里凡是 `{{}}` 开头的地方，
系统会明确报出待补清单。

```bash
cd xhs
python scheduler.py --date 2026-11-02 --dry-run   # 看排期和待补槽位
python scheduler.py --date 2026-11-02              # 真实发布
```
